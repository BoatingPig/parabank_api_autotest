### 组五：月份语义（`@pytest.mark.validation`）

| # | 用例 | 请求 | 断言要点 | 预期 | 结果 |
|---|---|---|---|---|---|
| 18 | `test_all_is_no_filter` | `month/All/type/All` | ID 集合 `==` 全量 | `All` 是魔法值 | ✅ |
| 19 | `test_chinese_month_filters_same_month` | `month/{最近一条的月}月/type/All` | 该 ID 必须命中；且返回的每条都属于该月 | 中文月份过滤生效 | ✅ |
| 20 | `test_matches_previous_year_december` | `month/12月/type/All` | `{12145,12256} ⊆ 结果` | 只比 MONTH，忽略年份 | ✅ |

> 第 19 条是「不硬编码日期」的典型写法：从接口返回里取一条流水的月份，再用它去查。断言「过滤是否生效」这个性质，而不是「某个月返回几条」。
> 第 20 条能硬编码 `12月`，因为种子 SQL 里那两条的月份固定为 12（`YEAR(CURRENT_DATE-1 YEAR)-12-11`）。
> 第 21 条的判据是三段式：**允许过滤，允许报错，唯一不能接受的是静默返回全量**。这是「无文档时如何定义预期」的标准形态。

## 七、用例写法上的三条固定套路

从这 44 条里能抽出来的可复用模式：

### 1. 「性质断言」代替「数值断言」

```python
# ❌ 会随种子数据漂移而失效
assert len(tx.rows(resp)) == 5

# ✅ 无论哪天跑都成立
assert pick["id"] in tx.ids(resp)
for t in resp.json:
    assert month_of(t["date"]) == month
```

适用于：日期过滤、按月过滤、按类型过滤——一切依赖「相对今天」的数据。

### 2. 「三段式」预期（无文档时用）

```python
assert resp.status_code != 500        # 绝不能崩
if resp.status_code == 200:
    assert tx.ids(resp) < base        # 认了就过滤
# 否则就是 4xx，允许
```

判据是：**允许 A，允许 B，唯一不能接受的是 C。** 比硬写「应该返回 400」更抗变更。

### 3. 「不泄漏」代替「必须拒绝」

```python
if resp.status_code == 200:
    leaked = tx.ids(resp) - ALL_IDS
    assert not leaked, f"注入了其他账户的流水 {sorted(leaked)}"
else:
    assert resp.status_code in (400, 403)
```

安全类用例的通用写法：**不限定防护手段，只限定「不能出现什么结果」**。这样开发换防护策略时用例不会误报。
